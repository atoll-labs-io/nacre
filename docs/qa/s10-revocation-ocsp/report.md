## Findings
Status rule: **verified** means the steps were replayed and reproduced the defect, and an evidence file holds it; **probable** means it was seen once, or no evidence file could be kept; **unverified** means it is suspected from what the surface showed, not seen happening.

### Finding 1 — Through `RevocationSource`, a replayed OCSP response reads `kind() = Unavailable`
Severity: minor
Status: verified
Steps to reproduce:
1. Serve, at the walk leaf's responder `http://127.0.0.1:18392/`, a valid CA-signed response carrying a fixed nonce.
2. Call `HttpOcspSource::allowing_loopback().revocation(leaf, ca)` and print `kind()` of the returned `nacre_core::Error`, then `kind()` of the `nacre_revocation::Error` it carries as `source()`.
3. Do the same with `HttpOcspSource::new()` on a leaf whose responder is `http://10.1.2.3/`.
Capture: docs/qa/s10-revocation-ocsp/c2-s02-responder-error.txt; docs/qa/s10-revocation-ocsp/replay-findings.txt (replay)
Expected: `NonceMismatch` is mapped, and documented, as `InvalidSignature` ("a forged or replayed answer"), `NonPublicAddress` as `InvalidInput`; ADR-0012 says an application answering an untrusted party shows the kind only.
Observed: the caller of the trait reads `Unavailable` for every OCSP refusal, a replayed response and a refused address included; only the boxed inner error carries the kind this story chose. The mapping `Revocation(_) => Unavailable` is `nacre-core`'s (`crates/nacre-core/src/error.rs:28`), outside this story's `Owns`; it is the first walk's finding 3, unchanged, which fix run 1 left to s39 as the lead asked (`docs/plans/s10-revocation-ocsp.md`, Fix run 1).

## Not seen
- The OCSP answer of the bench's own `pki` container (busybox httpd) — the walk did not start the bench containers; it ran the same CGI script over a copy of the same s02 PKI at the same URL with its own server, and ran `tests/bench.rs` against that. The CI `conformance` job runs it against the bench.
- A public OCSP responder, and pre-signed responses as public CAs serve them — the driver reaches only the servers it started; behaviour on a real network or against a real CA is not shown.
- An RSA-signed OCSP response — the walk PKI and both corpora are P-256; the RSA path is shared with CRLs and was seen in s09's QA, not here.
- The 30 s timeout of `HttpOcspSource` — no scenario served a slow answer.
- A DNS name resolving to a non-public address other than `localhost` (DNS rebinding) — reaching it needs a resolver or a zone the driver does not start.
- `Error::Random` (a failing system random generator) — no scenario can make `getrandom` fail from outside the process.
- The CI fuzz job on GitHub Actions — a remote service the driver did not start; a 60 s run was made locally instead.
