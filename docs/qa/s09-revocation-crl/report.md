## Findings
Status rule: **verified** means the steps were replayed and reproduced the defect, and an evidence file holds it; **probable** means it was seen once, or no evidence file could be kept; **unverified** means it is suspected from what the surface showed, not seen happening.

### Finding 1 — Through `RevocationSource`, a refused distribution point reads `kind() = Unavailable`
Severity: minor
Status: verified
Steps to reproduce:
1. In a crate depending on `nacre-revocation` (feature `http`) and `nacre-core`, take a certificate whose distribution point is `http://10.1.2.3/ec.crl` (or `http://169.254.169.254/…`).
2. Call `HttpCrlSource::new().revocation(certificate, issuer)` and print `kind()` of the returned `nacre_core::Error`, then `kind()` of the `nacre_revocation::Error` it carries as `source()`.
3. Do the same with an empty certificate.
Capture: docs/qa/s09-revocation-crl/c2-http-source-error.txt, replay-findings.txt (replay)
Expected: the new `Error::NonPublicAddress` is documented, and mapped, as `InvalidInput`: the certificate names an address the source will not reach, a property of the input that retrying does not change. ADR-0012 says an application answering an untrusted party shows the kind only.
Observed: the caller of the trait reads `Unavailable` ("service unavailable") for the refusal, as for an unreadable certificate; only the boxed inner error says `NonPublicAddress` / `InvalidInput`. An application that shows or acts on the kind treats a refused, possibly hostile, distribution point as a transient outage. The mapping `Revocation(_) => Unavailable` is `nacre-core`'s (`crates/nacre-core/src/error.rs:28`), outside this story's `Owns`; the first walk noted it for an invalid certificate argument, and fix run 1 makes it reach a security refusal too.

## Not seen
- The CRL download from the bench's own `pki` container (busybox httpd) — the walk did not start the bench containers; it served the same s02 files at the same URL with its own static server and ran `tests/bench.rs` against that. The CI `conformance` job runs it against the bench.
- A DNS name that resolves to a non-public address other than `localhost` (DNS rebinding) — reaching it needs a resolver or a zone the driver does not start.
- The `[::1]` download with `allowing_loopback()` — the walk's server listened on IPv4 only, so the attempt ended in `ConnectionRefused`; the refusal of `[::1]` by `new()` was seen.
- The 16 MiB body limit and the 30 s timeout of `HttpCrlSource` — no scenario served an oversized or slow answer.
- A public distribution point — the driver reaches only the servers it started, so no CRL was fetched from a public address; behaviour on a real network or against a real CA is not shown.
- The CI fuzz job on GitHub Actions — a remote service the driver did not start; a 60 s run was made locally instead.
