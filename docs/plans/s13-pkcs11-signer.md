## Story
A `Signer` that signs with a key kept on a PKCS#11 token.
1. Module, PIN login, key and certificate by label or id, ECDSA P-256 (`r||s` → DER) and RSA PKCS#1 v1.5.
2. CI: a SoftHSM-signed PDF is `PAdES-BASELINE-B` for DSS.
3. Wrong PIN → error with the token's state (count low, final try, locked); no panic, no signature.
4. PIN zeroized, never in an error or a log (concrete form above).
5. Manual YubiKey run (PIV 9c, `libykcs11`) recorded in `crates/nacre-pkcs11/MANUAL.md` with DSS's report.

## The pivot
Always-authenticate keys are signed through `sign_init`, a context-specific login, then a raw `C_Sign` taken from the same module's function list. Ways it could be wrong:
- `libykcs11` does not mark 9c always-authenticate, or refuses the context login: then the plain `session.sign` path runs, or the manual run fails with `UserNotLoggedIn`; compare the person's `MANUAL.md` result with SoftHSM's `always_authenticate_key_signs_twice`.
- The second load does not reach the same module instance (another path string, a module that refuses to be loaded twice): `C_Sign` then answers `CRYPTOKI_NOT_INITIALIZED` or `SESSION_HANDLE_INVALID`; `always_authenticate_key_signs_twice` catches it on SoftHSM, MANUAL.md on the YubiKey.
- Ubuntu's SoftHSM 2.6.1 in CI does not support context-specific login (spikes ran on 2.7.0): the always-authenticate test fails in `conformance.yml` only; read its log before suspecting `raw.rs`.
Second place to look: the PIN's lifetime in `open` (task 5, step 7) and the setup session's logout in `tests/support` (a missed logout makes the wrong-PIN test pass for the wrong reason, `UserAlreadyLoggedIn`).

## Test strategy
Automated, 9 tests, within `Test budget` 25:
- Unit (inside `src/`): `every_variant_has_its_kind`, `pin_state_follows_the_token_flags` (task 1), `raw_ecdsa_becomes_minimal_der` (task 3) — private mappings no token can reach in full.
- Service against SoftHSM (`tests/softhsm.rs`, ignored, `conformance.yml`): ECDSA by label, RSA by id, wrong PIN, always-authenticate, missing key — one test per rule the signer owns.
- Conformance (`tests/conformance.rs`, ignored, CI): the DSS level criterion 2 names.
Not tested automatically, by design: the YubiKey (manual, task 7); `FinalTry` and `Locked` on a token (SoftHSM never raises them; the unit mapping covers them); the PIN's zeroization itself (no safe way to read freed memory; covered by the type and the review).
Visual checks: none (library). Full suite and clippy once, at the end (task 8).

Fix run (review majors, owner's decision of 2026-10-22): `open` refuses `UserAlreadyLoggedIn` with `Error::AlreadyLoggedIn`, and a signer whose context-specific PIN the token refuses drops it and answers `Error::PinRefused` from then on, without calling the token.
